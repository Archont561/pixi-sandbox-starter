# pixi-sandbox starter

A ready-to-run [Pixi](https://pixi.sh) project with
[Pixi Sandbox](https://github.com/Archont561/pixi-sandbox) already configured. Everything in this
repository is generated from one published release — there is no setup step.

## Use it

1. Press **Use this template** and create a repository under your own owner.
2. Clone it and run the development task:

```sh
pixi run dev
```

3. Push to `main`. The included publisher packs your locked environment and pushes a
self-contained sandbox branch, using your repository's own `GITHUB_TOKEN`.

Opening it in a Codespace or any devcontainer works the same way: the pixi image
arrives with `git`, `gh` and the `pixi-sandbox` CLI already installed.

No `pixi-sandbox init`, no workflow copying, no version to choose, and no token owned
by anyone else.

## What is generated

These files are owned by pixi-sandbox `0.7.0` and are regenerated by
`pixi-sandbox init`. Edit them only if you are ready to own them:

- `.github/workflows/publish-sandbox.yml` — packs and publishes the sandbox branch
- `.github/workflows/relock.yml` — refreshes `pixi.lock` on pull requests
- `scripts/restore.sh` — offline restore launcher for an airlocked host
- `pixi-sandbox.toml` — the reviewed publish plan; written once, then yours

`pixi.toml`, `pixi.lock`, `.gitignore`, `.devcontainer/` and this README are yours
from the start.

## Updating

This repository is a snapshot of `v0.7.0`. A newer pixi-sandbox release produces a new
starter revision; it does not change repositories already created from this template.
The canonical starter's `main` is replaced with one parentless commit per update;
immutable `pixi-sandbox-vX.Y.Z` tags retain previous snapshots. This does not rewrite
your own repository. Prefer **Use this template** to following starter main with pulls.
Your own repository upgrades itself through the weekly upgrade lane in the publisher
workflow, which opens a reviewable pull request.
